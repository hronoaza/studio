# HRONOAZA Audio Studio — 1.1

Самостійний вебдодаток на Vanilla JavaScript, HTML5 Canvas і Web Audio API. Генерує синусоїдальну несучу 136.10 Гц з амплітудною модуляцією, відображає осцилограму та семплові піки після компресора.

## Статус перевірки

Пакет містить виправлений рушій, UI, маніфест і тести. Пройдено 13 автоматичних перевірок конфігурації та життєвого циклу в Node.js із контрольованими замінниками AudioContext/AudioNode. Це не перевірка цифрової обробки звуку в браузері.

Підготовлено 22 браузерні перевірки на OfflineAudioContext і вибрані асинхронні регресії. Їх тут **не виконано**: браузер Chromium відсутній, завантаження завершилося мережевими помилками. Візуальна перевірка та встановлення через маніфест також не виконані. Докладніше: [VALIDATION.md](../../docs/provenance/migrations/audio-studio-1.1/VALIDATION.md). Початкові фрагменти та виправлення зіставлено в [AUDIT.md](../../docs/provenance/migrations/audio-studio-1.1/AUDIT.md).

## Запуск локально

1. Розпакуйте проєкт і відкрийте термінал у папці з index.html.
2. Запустіть статичний сервер:

```bash
python -m http.server 8000
```

3. Відкрийте [застосунок](http://localhost:8000/index.html).
4. Зменште системну гучність та натисніть «Запустити». Автоматичного запуску звуку немає.

ES-модулі потрібно відкривати через HTTP(S), а не подвійним кліком через file://. Для самого застосунку npm і серверна логіка не потрібні.

## Специфікація

| Параметр | Значення |
|---|---|
| Несуча | 136.10 Гц, sine |
| Базовий gain / глибина AM | 0.45 / 0.10 |
| Огинаюча до компресора | 0.405–0.495 у сталому режимі |
| Старт / стоп / зміна режиму | Лінійні рампи 0.8 / 0.5 / 0.3 с |
| threshold / knee / ratio | −2 dB / 6 dB / 12:1 |
| attack / release | 0.003 / 0.100 с |
| AnalyserNode.fftSize | 512 |
| Пік-метр | OK: p < 0.9; WARN: 0.9 ≤ p < 0.98; LIMIT: p ≥ 0.98 |

| Режим | Частота модулятора | Період, приблизно |
|---|---|---|
| M1 | 136.10 Гц | 7.35 мс |
| M2 | 136.10 / Math.sqrt(2) Гц | 10.39 мс |
| M3 | 136.10 / Math.sqrt(3) Гц | 12.73 мс |

Обчислення використовують повну точність JavaScript. Округлення до 96.24 та 78.58 Гц виконується лише для відображення. Несуча не перемикається. Це AM на звукових частотах, не повільний LFO.

Основний тракт: carrier → carrierGain → outputGain → compressor → analyser → destination. Модулятор під’єднаний через modGain до carrierGain.gain; базове значення цього AudioParam дорівнює 1.

Модель до компресора: x(t) = G(t) × [1 + 0.1 sin(2π f_mod t + φ_mod)] × sin(2π × 136.1 t + φ_carrier). У сталому режимі G = 0.45. Числа 0.405–0.495 є межами огинаючої, а не межами миттєвих додатних значень хвилі.

## API рушія

```js
import { AudioEngine } from './audio-engine.js';
const engine = new AudioEngine();
// Викликати start() з обробника дії користувача.
await engine.start('M1');
await engine.setMode('M2');
await engine.stop();
// При остаточному демонтажі:
await engine.dispose();
```

- start(), setMode(), stop() повертають Promise<boolean>: true — операцію завершено, false — проігноровано або скасовано. Помилки повертаються через відхилений Promise.
- start() утримує стан starting до завершення стартової рампи; setMode() — changing до завершення рампи частоти. Повторні конфліктні команди не ставляться в чергу.
- stop() може перервати старт або зміну режиму. Осцилятори зупиняються за часом AudioContext, а не настінним таймером.
- hardReset() синхронно інвалідує старі завершення та звільняє граф. Контекст зберігається для повторного використання; dispose() також закриває його.
- Якщо контекст призупинено, його аудіочас не рухається; очікування рампи триває до відновлення або hardReset().
- state, isBusy, isPlaying, currentMode й analyser доступні для UI. isPlaying означає наявність графа, включаючи рампи; стан відтворення браузера також залежить від ctx.state. Внутрішні вузли містяться в graph; UI їх не змінює.
- attachResponsiveOscilloscope() у script.js повертає функцію очищення requestAnimationFrame і ResizeObserver. DPR перевіряється також у кадрі, включно з перенесенням вікна між екранами.

## Автоматичні тести

Потрібний Node.js 22 або новіший. Node-тести не потребують npm-залежностей:

```bash
npm test
```

Для headless-рендерингу:

```bash
npm install
npx playwright install chromium
npm run test:audio
```

Runner сам запускає локальний HTTP-сервер і закриває його після перевірки. Код виходу 1 означає помилку перевірки або запуску. Після завершеного браузерного запуску створюється test-results.json з вимірами. На Linux можуть знадобитися системні залежності Playwright. Альтернатива без Playwright: відкрийте [офлайн-тест](http://localhost:8000/offline-audio-test.html) через запущений статичний сервер.

OfflineAudioContext використовує ту саму фабрику createGraph(), що й рушій. Канал 0 фіксує сигнал до компресора, канал 1 — після. Тестується 44.1 і 48 кГц; для M1 DC оцінюється за 10 секунд сталого сигналу, тобто за 1361 повним періодом. Тести імпульсу та гучного пакета вимірюють реакцію компресора й не заявляють true-peak захисту. [MDN: OfflineAudioContext](https://developer.mozilla.org/en-US/docs/Web/API/OfflineAudioContext).

Цей модуль входить до HRONOAZA Studio і не визначає окрему політику публічного розгортання. Спосіб deployment має задаватися на рівні репозиторію та окремого release/deployment review.

## Маніфест та межі

Маніфест підключено в index.html. SVG має sizes: any, PNG — фактичні розміри; start_url, scope та id відносні до підкаталогу проєкту. Доступність встановлення залежить від браузера. Service Worker і гарантоване завантаження без мережі в цій редакції відсутні. «OfflineAudioContext» означає рендеринг у пам’ять, а не офлайн-кеш застосунку. [MDN: іконки маніфесту](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest/Reference/icons).

Компресор не є brick-wall або true-peak лімітером. Семпловий пік після компресора може відрізнятися від аналітичної межі 0.495 перед ним; не слід переносити цю межу на вихід без вимірювання. Візуальний пік-метр може пропускати короткі події між кадрами. DC-фільтра немає: у M1 очікувана DC-складова до компресора дорівнює 0.0225 cos(φ_mod − φ_carrier). Плавна зупинка не є DC-фільтром, а аварійний обрив може клацнути. Цифровий рівень не гарантує безпеки слуху. [W3C Web Audio API](https://www.w3.org/TR/webaudio/).
