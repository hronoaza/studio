This document closes the remaining D8B-specific design choices required before

## 1. ProvenanceItemId generation

### Selected candidate

`ProvenanceItemId` uses the same representation family as the accepted D8A
capture identity:

```text
128-bit / 16 opaque bytes
generated by OS-backed CSPRNG
all-zero reserved invalid
finite fail-closed retry
```

The D8B generator is logically independent from the D8A `SourceCaptureId`
generator.

Required distinction:

```text
SourceCaptureId != ProvenanceItemId
```

even when both use the same 128-bit generation family.

### Uniqueness domain

The declared domain is:

> all D8B provenance items emitted by all compliant producer instances that may
> contribute to the same provenance/evidence ecosystem, including across
> process/machine restart and producer-version transition.

The design provides probabilistic uniqueness, not mathematical impossibility of
collision.

The implementation must never intentionally derive `ProvenanceItemId` from:

- SourceCaptureId;
- relationship IDs;
- state version;
- source payload;
- canonical digest;
- timestamps/process IDs alone.

### Failure semantics

If a valid item ID cannot be produced:

```text
no ProvenanceItemId
-> no envelope publication
```

There is no weak fallback.

## 2. Schema identity

### Production schema identity

The D8B v1 schema must have one fixed 128-bit opaque `schemaId`.

The schema ID identifies the semantic/canonical schema family; version fields
carry evolution within that family.

Candidate registry label:

`SOAM.D8B.PROVENANCE.ENVELOPE`

Candidate version:

```text
schemaMajor = 1
schemaMinor = 0
canonicalEncodingVersion = 1
```

The production `schemaId` must be fixed once in a registry document before
runtime implementation is merged.

It must not be generated per build or per process.

### Versioning rule

- incompatible field/meaning changes -> schema major change;
- compatible metadata extension that does not reinterpret existing bytes ->
  schema minor change when representable by the encoding;
- any canonical byte-layout rule change -> canonical encoding version change
  and, if old bytes would be reinterpreted, schema major change.

No silent reinterpretation of v1 bytes is allowed.

## 3. Producer identity

### Producer family

D8B v1 has one fixed producer-family identity.

Candidate registry label:

`SOAM.D8B.PROVENANCE.PRODUCER`

Candidate producer version:

```text
producerMajor = 1
producerMinor = 0
```

`producerId` identifies the producer family, not a process instance and not a
machine.

It is not authentication.

### Implementation revision

`implementationRevision` identifies the exact reviewed implementation revision
that produced the envelope.

Wire representation remains:

```text
implementationRevisionKind: u8
implementationRevision: 32 bytes
```

v1 production rule:

- kind 0 is permitted only for design/test fixtures or explicitly
  non-revision-bound evidence;
- accepted production D8B envelopes should use kind 1;
- kind 1 means SHA-256 over an accepted canonical implementation-revision
  manifest.

The revision manifest format must be defined with implementation work so the
digest is reproducible independently of one compiler/build directory.

`implementationRevision` does not authenticate the producer.

---

## 4. Dependency-kind registry

D8B v1 production dependency kinds are fixed as follows:

| Tag | Kind | Meaning |
|---:|---|---|
| 1 | SOURCE_CAPTURE_CONTRACT | accepted D8A source-capture contract materially consumed |
| 2 | CANONICAL_ENCODING_SPEC | CanonicalEnvelopeV1 specification |
| 3 | DIGEST_PROFILE | SHA-256 + D8B domain-separation profile |
| 4 | ADDITIONAL_RUNTIME_CONTRACT | reserved for another materially participating runtime contract |

Tags 0 and 255 are reserved.

Tags 5..254 are unassigned in v1.

The manifest MUST NOT duplicate:

- schema identity already in EnvelopeHeader;
- producer identity already in EnvelopeHeader.

Dependency entries are evidence of material participation, not trust/admissibility
approval.

D8C decides whether a dependency version is acceptable/current/retired.

---

## 5. CanonicalEnvelopeV1 acceptance review

The current wire-format candidate is internally coherent.

Reviewed properties:

- fixed 8-byte magic;
- portable fixed-width integer encodings;
- `std::size_t` normalized to u64;
- schema-owned BridgeStatus tags;
- IEEE-754 binary64 bit preservation;
- each semantic field has one canonical owner;
- digest excluded from its own preimage;
- dependency entries are fixed-width;
- manifest order canonicalized independently of insertion order;
- SourceRecordReference presence byte is fixed to 0 in v1;
- arbitrary parsed bytes do not become trusted provenance.

No design blocker was found in the byte-layout candidate.

## 7. Restricted-origin C++ API design

### Public types

Candidate public value types:

```cpp
class ProvenanceItemId;
class CanonicalDigest;
class ProductionProvenanceEnvelope;
class ProductionProvenanceEnvelopeProducer;
```

`ProvenanceItemId`:

- immutable 16-byte value;
- no public default constructor;
- no public arbitrary-byte constructor;
- read-only bytes accessor;
- copy/move preserve identity.

`CanonicalDigest`:

- immutable 32-byte value;
- no public arbitrary construction for trusted-envelope creation;
- read-only bytes accessor.

### Envelope

`ProductionProvenanceEnvelope` is restricted-origin:

- no public default constructor;
- no public aggregate initialization;
- no public constructor from raw fields;
- no public constructor from canonical bytes;
- no public digest injection;
- no public SourceCaptureId replacement;
- immutable after publication.

Public accessors may expose immutable/header/source values and canonical digest.

### Producer

Candidate surface:

```cpp
class ProductionProvenanceEnvelopeProducer final {
public:
    [[nodiscard]]
    std::optional<ProductionProvenanceEnvelope> produce(
        const ProductionRelationshipSourceSnapshot& snapshot) const;
};
```

The ordinary caller supplies only the accepted D8A snapshot.

The caller does not supply:

- item ID;
- producer identity;
- schema identity;
- canonical digest;
- dependency manifest;
- SourceCaptureId.

These are owned by the accepted D8B implementation/configuration.

## 8. Internal seams

Failure-path testability must not alter public API declarations.

Internal/test-only seams may inject:

- ProvenanceItemId random-source failure;
- duplicate/all-zero item-ID candidates;
- canonical encoder failure;
- dependency-manifest preparation failure;
- SHA-256 provider failure.

These seams must live in non-installed/internal headers or implementation
factories.

No `#ifdef TEST` may change the canonical installed public class definitions.

---

## 9. Publication ordering

Candidate implementation ordering:

```text
accepted immutable D8A snapshot
-> reserve ProvenanceItemId
-> prepare fixed producer/schema metadata
-> prepare SourceBinding from snapshot
-> prepare SourceMeasurements from snapshot
-> prepare DependencyManifest
-> canonical encode detached bytes
-> compute CanonicalDigest
-> validate internal invariants
-> construct/publish immutable ProductionProvenanceEnvelope
```

All potentially throwing preparation occurs before publication.

No D8B step mutates live mesh state.

---

## 10. Compile-fail misuse gates

Implementation acceptance requires compile-fail rejection of at least:

1. default construction of `ProvenanceItemId`;
2. arbitrary-byte construction of trusted `ProvenanceItemId`;
3. default construction of `ProductionProvenanceEnvelope`;
4. raw-field construction of envelope;
5. caller-selected `ProvenanceItemId`;
6. caller-replaced `SourceCaptureId`;
7. caller-injected `CanonicalDigest`;
8. mutation of an envelope identity/digest/source binding;
9. construction of trusted envelope from arbitrary canonical bytes.

---

## 11. Runtime/conformance gates

Before implementation acceptance:

- all existing D8A/C2/D7 tests remain green;
- D8B positive/negative/failure tests pass;
- fixed canonical vectors match exact expected bytes;
- fixed digest vectors match exact expected SHA-256;
- dependency insertion order cannot alter canonical bytes;
- repeated wrapping of the same D8A snapshot preserves SourceCaptureId but gets
  a new ProvenanceItemId;
- failed D8B production publishes nothing and mutates no live runtime state;
- ASan/UBSan and TSan remain clean on supported CI path;
- public declarations are configuration-invariant.
